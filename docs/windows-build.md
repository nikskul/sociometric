# Сборка приложения для Windows

Из обычного веб-сервиса получается настольное приложение: пользователь
нажимает ярлык, в браузере открывается интерфейс, в трее появляется значок
с пунктом «Выход». Устанавливать Java пользователю не нужно — среда Java
вшита внутрь сборки.

Само приложение при этом не меняется: те же расчёты, та же база, тот же
интерфейс. Разница только в запуске.

## Что понадобится

| | Зачем |
|---|---|
| Windows 10 или 11 x64 | Собирать нужно на Windows: `jpackage` берёт модули из установленного JDK и системные библиотеки Windows. Кросс-сборки не существует. |
| JDK 21 (Temurin, Oracle или Zulu) | Из него `jpackage` делает установщик и вшивает среду Java |
| Maven 3.9+ | Обычная сборка проекта |
| WiX Toolset 3.x | Только для `.msi`. Для переносимой папки не нужен |
| Python 3 (необязательно) | Чтобы перегенерировать значок, если он изменится |

Проверить JDK и Maven:

```powershell
javac -version     # должно быть javac 21
mvn -version
```

## Сборка из WSL: сначала скопируйте проект в Windows

Если проект лежит в WSL, путь выглядит как
`\\wsl.localhost\Ubuntu\home\...`. По такому пути Maven работает в разы
медленнее, а `jpackage` может упасть на блокировках файлов. Соберите из
обычной папки Windows:

```powershell
robocopy . C:\dev\sociometric /MIR /XD .git target
cd C:\dev\sociometric
```

Скрипт это проверяет и останавливается с подсказкой, если его запустили
из WSL.

## WiX и ошибка «No NuGet sources are defined or enabled»

`jpackage` из JDK 21 собирает `.msi` **только через WiX 3.x** — из его состава
берутся `candle.exe` и `light.exe`. WiX 4 и 5 в JDK 21 не поддерживаются: их
поддержка появилась только в JDK 22.

Установка через `dotnet tool install` падает с «No NuGet sources», если у .NET
не настроен источник пакетов. Три выхода, от простого к полному:

**1. Собрать переносимую папку — WiX не нужен вообще.** Приложение
полностью работоспособно, ставить ничего не нужно:

```powershell
powershell -ExecutionPolicy Bypass -File build-windows.ps1 -Type app-image
```

Если запустить скрипт без `-Type` и WiX не найдётся, он сам соберёт
`app-image` и предупредит об этом.

**2. Настроить NuGet и поставить WiX 3:**

```powershell
dotnet nuget add source https://api.nuget.org/v3/index.json
dotnet tool install --global wix --version 3.11.2
```

**3. Скачать WiX 3 напрямую, без NuGet:** установщик
`WiX-v3.11.2-win-x86.msi` со страницы релизов
<https://github.com/wixtoolset/wix/releases>. Это обычный `.msi`, ставится
двойным щелчком.

После любого из вариантов 2 и 3 скрипт найдёт WiX сам.

## Кодировка скрипта

`build-windows.ps1` сохранён в UTF-8 **с ровно одним BOM** и переводами строк
LF. Windows PowerShell 5.1 читает `.ps1` в системной кодировке ANSI, и без BOM
кириллица в сообщениях превращается в байты, которые ломают разбор скрипта
(«отсутствует блок Finally», «Missing argument»).

BOM должен быть **один**. Лишний второй BOM превращается в обычный символ
U+FEFF перед `<#`, блочный комментарий не открывается, и PowerShell 7 читает
следующие строки как код:

```
ParserError: Missing argument in parameter list.
```

Если правите файл вручную — не сбивайте BOM. Автоматическая проверка этого
есть в `static.test.js`, запускается вместе с остальными фронтенд-тестами.

## Если PowerShell ругается на синтаксис

Пересоберите файл в UTF-8 **с одним** BOM, например так:

```powershell
$text = Get-Content build-windows.ps1 -Raw -Encoding UTF8
[System.IO.File]::WriteAllText(
    "$PWD\build-windows.ps1", $text,
    (New-Object System.Text.UTF8Encoding $true))
```

## Сборка

```powershell
# установщик .msi — то, что нужно обычному пользователю
powershell -ExecutionPolicy Bypass -File build-windows.ps1

# переносимая папка без установки
powershell -ExecutionPolicy Bypass -File build-windows.ps1 -Type app-image

# повторная сборка без тестов (быстрее)
powershell -ExecutionPolicy Bypass -File build-windows.ps1 -SkipTests

# установка для всех пользователей (нужны права администратора)
powershell -ExecutionPolicy Bypass -File build-windows.ps1 -AllUsers
```

Готовые файлы появляются в `target\windows`.

Скрипт сам проверит, что в jar действительно настольная точка входа. Если
забудете профиль `desktop`, установщик молча запустил бы обычный сервер на
порту 8080 — без браузера и без трея, — и сборка прервётся с понятной ошибкой.

## Как это устроено

```
Sociometric.exe            запускается с ярлыка
  └─ своя среда Java       внутри папки приложения
      └─ DesktopLauncher   выбирает свободный порт, кладёт базу в профиль
          └─ приложение    пользователю, открывает браузер
              └─ трей      «Открыть приложение» и «Выход»
```

Ключевые решения:

**Порт выбирает система.** Запуск идёт с `server.port=0`, поэтому приложение
не откажется стартовать из-за занятого 8080. Реальный порт приложение читает
само и открывает в браузере именно его.

**Данные лежат в профиле пользователя**, а не в рабочем каталоге ярлыка:
`%LOCALAPPDATA%\Sociometric`. Оттуда же берётся журнал `sociometric.log`.
У ярлыка рабочий каталог системный, писать в него нельзя.

**Повторный запуск не плодит копии.** Первый экземпляр оставляет заметку
`run.properties` с pid и портом. Второй запуск её находит, открывает вкладку
в уже работающем приложении и выходит.

**Демо-данные создаются только при пустой базе.** При первом запуске
появляется учебный опрос «8А класс», дальше он не трогается: если база не
пуста, ничего не добавляется.

**Выход — в трее.** Окна у приложения нет, поэтому процесс живёт, пока им
 пользуются. Пункт «Выход» в трее закрывает приложение штатно: база
закрывается, файлы не остаются повреждёнными. Если трея в системе нет,
показывается маленькое окно с адресом и кнопкой «Выход».

## Установка у пользователя

**Через `.msi`.** Скопировать установщик и запустить. Дальше всё как у
обычной программы: ярлык в меню «Пуск», значок на рабочем столе, удаление
через «Панель управления». По умолчанию ставится в профиль пользователя —
права администратора не нужны.

**Папкой.** Скопировать папку `Sociometric` на компьютер и запустить
`Sociometric.exe`. Ничего не устанавливается, но при копировании на другой
компьютер база не переносится: она лежит в `%LOCALAPPDATA%`.

## Где лежат данные и как их перенести

| Что | Где |
|---|---|
| База | `%LOCALAPPDATA%\Sociometric\data\sociometric.mv.db` |
| Журнал | `%LOCALAPPDATA%\Sociometric\sociometric.log` |
| Заметка о запуске | `%LOCALAPPDATA%\Sociometric\run.properties` |

Перенести данные на другой компьютер: скопировать папку `data`, на новом
компьютере положить на место. При запуске база откроется как обычно.

**Резервная копия — это просто копия папки `data`.** Копировать её нужно
при закрытом приложении, иначе файл базы может оказаться недописанным.

## Если что-то пошло не так

**Приложение не открывается в браузере.** Откройте журнал:

```powershell
Get-Content "$env:LOCALAPPDATA%\Sociometric\sociometric.log" -Tail 40
```

**Порт занят или приложение молчит.** Оно берёт любой свободный порт
сам, поэтому помешать этому почти нечем. В журнале будет строка
`Tomcat started on port NNNNN` — по ней и проверяйте.

**Значка нет в трее.** Некоторые сборки Windows прячут область уведомлений.
Значок может оказаться в списке скрытых — проверьте стрелку «^» у часов.
Если трея нет вовсе, приложение покажет маленькое окно с кнопкой «Выход».

**Где мои данные?** Путь печатает лаунчер:

```powershell
.\Sociometric.exe --paths
```

**Приложение запустилось как сервер, без браузера и трея.** Сборка сделана
без профиля `desktop`. Пересоберите с ним — скрипт такое отлавливает, но
если собирали вручную, проверьте, что в манифесте jar
`Start-Class: ru.sociometric.desktop.DesktopLauncher`.

**Забыли, какие данные в базе.** Подсистема настольная, аутентификации нет:
кто получил доступ к приложению, тот получил доступ к опросам. Не ставьте
её на общий диск и не пробрасывайте порт наружу.

## Сборка вручную, без скрипта

```powershell
mvn clean package -Pdesktop
jpackage --type msi --name Sociometric --app-version 1.0.0 `
  --input target --dest target\windows `
  --icon src\main\windows\sociometric.ico `
  --java-options -Xmx1g --java-options -Djava.awt.headless=false `
  --win-shortcut --win-menu --win-per-user-install --win-dir-chooser
```

Обязателен профиль `desktop` — он ставит `Start-Class` на лаунчер.
Установщик читает точку входа из манифеста jar, поэтому `--main-class` и
`--main-jar` передавать **нельзя**: класс лежит внутри `BOOT-INF/classes` и
через classpath не находится. `jpackage` возьмёт `Main-Class` из манифеста сам.

Два момента, на которых спотыкаются:

- **`--win-per-user-install` — флаг, без значения.** С ним установщик ставится
  в профиль пользователя и права администратора не нужны. Без флага — установка
  для всех, и нужны права администратора.
- **У `jpackage` в JDK 21 нет опции `--tool`.** Путь к WiX задать нельзя,
  `candle.exe` и `light.exe` ищутся в `PATH`. Если WiX стоит не в стандартном
  месте, добавьте его каталог в `PATH` перед вызовом:

```powershell
$env:PATH = "$env:USERPROFILE\.dotnet\tools;$env:PATH"
```

## Значок

`src\main\windows\sociometric.ico` — та же схема, что на вкладке
«Социограмма». Файл генерируется кодом, а не рисуется руками:

```powershell
python tools\make_icon.py
```

Если поменяются цвета статусов в `sociogram.js`, прогоните скрипт заново,
чтобы значок не разошёлся с интерфейсом.

## Ограничения настольной сборки

Стоит понимать заранее, чтобы не было сюрпризов:

- **Аутентификации нет.** Приложение доверяет тому, кто может до него
  дойти. Для работы на своём компьютере это нормально, для общей сети — нет.
- **Окна нет — только браузер.** Интерфейс открывается в браузере по
  умолчанию. Отдельного окна приложения не создаётся.
- **Не хранилище.** H2-файл рассчитан на одного пользователя и один
  экземпляр приложения. Одновременная работа нескольких копий на одной базе
  не поддерживается, для этого нужен сервер с настоящей СУБД.
- **Обновлений нет.** Новую версию ставят поверх старой обычным
  установщиком. Данные при этом сохраняются.
