# Социометрия по Морено

Веб-приложение для обработки социометрических опросов: участники выбирают друг друга,
приложение считает статусы, строит социограмму и показывает индексы группы.

Никакой аутентификации нет — приложение рассчитано на учебный стенд или одну команду.

---

## Что умеет

| Раздел | Содержание |
| --- | --- |
| **Настройки** | Название, лимит выборов, сбор антипатий, ранжированный опросник, пороги статусов |
| **Ввод** | Классическая форма (респондент выбирает по одному) и матрица (все пары сразу) |
| **Импорт** | CSV и XLSX, длинный и широкий формат, автоопределение разделителя |
| **Результаты** | Статусы, матрица, индексы, пары, графовые метрики, сравнение подгрупп |
| **Социограмма** | Три раскладки, экспорт в SVG/PNG, печать |
| **Эксперты** | Оценки каждого участника, Kendall W, корреляции со статусом |

## Запуск

Нужны JDK 21 и Maven. Node.js нужен только для тестов фронтенда.

```bash
mvn spring-boot:run
```

Открыть <http://localhost:8080>. При первом запуске создаётся демонстрационный опрос
(12 участников, 31 выбор) — выключается свойством `sociometric.demo-data-on-startup: false`.

Данные лежат в файловой H2 `./data/sociometric`. Чтобы начать с нуля, удалите каталог
`data`. Консоль H2 доступна на <http://localhost:8080/h2-console> (JDBC URL —
`jdbc:h2:file:./data/sociometric`, пользователь `sa`, пароль пустой).

## Тесты

```bash
mvn verify                    # 38 тестов Java + 46 проверок фронтенда
node src/test/js/run.js       # только фронтенд, если нужно быстро
```

Фронтенд проверяется тремя наборами:

- `static.test.js` — синтаксис, целостность разметки, отсутствие обращений к несуществующим элементам;
- `sociogram.test.js` — раскладка социограммы: отсутствие наложений, читаемость подписей;
- `app.test.js` — клиентская логика на поддельном DOM: лимиты, ранги, эксперты, индексы.

Проверки фронтенда выполняет `run-frontend-tests.sh` на фазе `test`, поэтому `mvn verify`
проверяет обе части. Скрипт ничего не требует от окружения: если Node.js не установлен,
он печатает предупреждение и завершается успешно, так что сборка на сервере без Node
не ломается. Первый запуск Maven в офлайне не сможет скачать `exec-maven-plugin` —
достаточно один раз собрать при доступе к сети, дальше всё работает офлайн.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/surveys/meta` | Справочник статусов и формул для UI |
| `GET` `POST` | `/api/surveys` | Список и создание опросов |
| `GET` `PUT` `DELETE` | `/api/surveys/{id}` | Один опрос |
| `GET` | `/api/surveys/{id}/result` | Полный расчёт: статусы, индексы, пары, граф |
| `PUT` | `/api/surveys/{id}/choices` | Заменить набор выборов |
| `GET` `POST` | `/api/surveys/{id}/experts` | Экспертные оценки |
| `POST` | `/api/surveys/{id}/import` | Загрузить CSV/XLSX |
| `GET` | `/api/surveys/{id}/export?format=csv\|xlsx` | Выгрузка |
| `GET` | `/api/surveys/{id}/template.csv` | Бланк под состав участников |

Пустые поля в ответах не выводятся (`non_null`), поэтому клиенту не нужно отличать
«нет значения» от нуля.

## Формат файлов импорта

Разделитель определяется автоматически: запятая, точка с запятой, таб или вертикальная черта,
что нашла в первой непустой строке. Первая строка — заголовок. Строки, начинающиеся с `#`,
пропускаются, кодировка UTF-8 с BOM читается.

**Длинный формат** — одна строка на один выбор:

```csv
from,to,kind,weight,rank
1,2,SYMPATHY,1,
2,1,SYMPATHY,1,
3,1,ANTIPATHY,1,1
```

**Широкий формат** — строка на респондента, колонки помечены кодами участников;
значение — `1` (выбрал), `0` (не выбрал) или `-1` (антипатия):

```csv
code,1,2,3
1,0,1,1
2,1,0,0
```

Названия колонок «кто выбрал», «тип», «вид», «вес», «ранг» распознаются по-русски
и по-английски. Коды, которых нет среди участников, пропускаются с предупреждением.

## Как считаются показатели

**Статусы** — по входящим выборам относительно среднего `μ` и стандартного отклонения `σ`.
При `μ − σ` участник набирает `σ + 1` баллов, при `μ + σ` — `σ − 1`; при равных числах
сравнение идёт по исходящим выборам, иначе по алфавиту. Без σ все, кроме изолированных,
считаются предпочитаемыми. Пороги по умолчанию рассчитываются автоматически под состав
группы, но их можно задать вручную.

| Статус | Смысл |
| --- | --- |
| «Звезда» | выбирают чаще всех |
| «Предпочитаемый» | выше среднего |
| «Принятый» | на уровне среднего |
| «Изолированный» | никто не выбрал |
| «Отвергаемый» | антипатий больше, чем симпатий |
| «Аутсайдер» | выбирает сам и не выбран |

**Индексы:**

- `gsc` — сплочённость группы: `2M / (n(n−1))`, где `M` — число взаимных пар.
  Формулу можно переключить на `mutualDoublePass` (свойство `sociometric.gsc-formula`),
  которая для ранжированного опросника с весами считает сумму произведений.
- `reciprocityIndex` — доля взаимных пар среди всех пар с хотя бы одним выбором.
- `density` — отношение числа связей к максимально возможному.
- `rejectedIndex` — доля участников, получивших хотя бы одну антипатию.
- `negativeStatusIndex` — доля участников с негативным статусом.
- `meanSelectionsPerPerson` — среднее число полученных выборов.

Подгруппы для сравнения выделяются по **ведущим цифрам кода**: «1А» и «1Б» попадают в
подгруппу «1», «2А» и «2Б» — в «2». Коды без цифр («1», «12») подгрупп не образуют.
Подгруппы меньше двух человек отбрасываются.

**Экспертные оценки.** Kendall W показывает согласованность экспертов (нужен минимум
двойной эксперт, иначе в UI пишется «нужно минимум два эксперта»). Пирсон и Спирмен
сравнивают оценку эксперта с количеством полученных выборов. При недостатке данных
все три поля возвращаются как `null`, а не как ноль.

## Структура

```
src/main/java/ru/sociometric/
  domain/       сущности и перечисления
  repository/   Spring Data JPA
  calculator/   расчёты, не зависящие от Spring
  service/      опросы, результаты, импорт, экспорт

src/main/resources/static/   index.html, app.js, sociogram.js, styles.css
src/test/java/                модульные и интеграционные тесты
src/test/js/                 проверки фронтенда на node
```
