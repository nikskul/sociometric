# Социометрия по Морено

Веб-приложение для обработки социометрических опросов: участники выбирают друг друга,
приложение считает статусы, строит социограмму и показывает индексы группы.

Приложение работает как локальный кабинет одной школы. По умолчанию слушает только
`127.0.0.1`; для сетевого доступа включите HTTP Basic и задайте отдельную базу для
каждой школы. Подробности — в разделе «Развёртывание для школы» ниже.

---

## Что умеет

| Раздел | Содержание |
| --- | --- |
| **Настройки** | Название, лимит выборов, сбор антипатий, ранжированный опросник, пороги статусов |
| **Ввод** | Классическая форма (респондент выбирает по одному) и матрица (все пары сразу) |
| **Импорт** | CSV и XLSX, длинный и широкий формат, автоопределение разделителя |
| **Результаты** | Статусы, матрица, индексы, пары, графовые метрики, сравнение подгрупп |
| **Социограмма** | Три раскладки, экспорт в SVG/PNG, печать |
| **Эксперты** | Оценки каждого участника, Kendall W, корреляции со статусом |

## Запуск

Нужны JDK 21 и Maven. Node.js нужен только для тестов фронтенда.

```bash
mvn spring-boot:run
```

Открыть <http://localhost:8080>. При первом запуске создаётся демонстрационный опрос
(12 участников, 31 выбор) — выключается свойством `sociometric.demo-data-on-startup: false`.

Данные лежат в файловой H2 `./data/sociometric`. Чтобы начать с нуля, удалите каталог
`data`. Консоль H2 по умолчанию выключена; для локальной разработки её можно включить
переменной `SOCIOMETRIC_H2_CONSOLE_ENABLED=true` (JDBC URL —
`jdbc:h2:file:./data/sociometric`, пользователь `sa`, пароль пустой).

## Развёртывание для школы

Каждой школе нужна отдельная установка и отдельный каталог базы. Не размещайте базы
нескольких школ в одном экземпляре приложения: изоляция организаций между собой
в этой версии не реализована. Для настольной сборки задайте каждой школе свой
`SOCIOMETRIC_HOME`; для серверной — свой `SOCIOMETRIC_DB_URL`.

Для доступной по сети установки задайте `SOCIOMETRIC_AUTH_ENABLED=true`,
`SOCIOMETRIC_ADMIN_USERNAME` и `SOCIOMETRIC_ADMIN_PASSWORD` (не короче 12 символов),
а `SOCIOMETRIC_SERVER_ADDRESS` замените на нужный интерфейс. Размещайте сервис за
HTTPS reverse proxy и не публикуйте H2 Console. По умолчанию она отключена.
Аутентификация — одна учётная запись администратора на экземпляр; индивидуальные
роли нескольких сотрудников пока не поддерживаются.

Вкладка «Опрос» содержит скачивание ZIP-копии базы и подтверждаемое удаление всех
данных экземпляра. Перед обновлением сохраните копию вне компьютера с приложением.
Демонстрационные данные при старте можно отключить через
`SOCIOMETRIC_DEMO_DATA_ON_STARTUP=false`.

Коммерческое предложение для первых пилотов и сценарий проверки готовности платить
описаны в [docs/commercial-pilot.md](docs/commercial-pilot.md).

## Тесты

```bash
mvn verify                    # 53 теста Java + 52 проверки фронтенда
node src/test/js/run.js       # только фронтенд, если нужно быстро
```

Фронтенд проверяется тремя наборами:

- `static.test.js` — синтаксис, целостность разметки, отсутствие обращений к несуществующим элементам, чистота бандла от тестовых точек входа;
- `sociogram.test.js` — раскладка социограммы: отсутствие наложений, читаемость подписей;
- `app.test.js` — клиентская логика на поддельном DOM: лимиты, ранги, эксперты, индексы.

Проверки фронтенда выполняет `run-frontend-tests.sh` на фазе `test`, поэтому `mvn verify`
проверяет обе части. Скрипт ничего не требует от окружения: если Node.js не установлен,
он печатает предупреждение и завершается успешно, так что сборка на сервере без Node
не ломается. Первый запуск Maven в офлайне не сможет скачать `exec-maven-plugin` —
достаточно один раз собрать при доступе к сети, дальше всё работает офлайн.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/surveys/meta` | Справочник статусов и формул для UI |
| `GET` `POST` | `/api/surveys` | Список и создание опросов |
| `GET` `PUT` `DELETE` | `/api/surveys/{id}` | Один опрос |
| `GET` | `/api/surveys/{id}/result` | Полный расчёт: статусы, индексы, пары, граф |
| `POST` | `/api/surveys/{id}/choices` | Сохранить выборы, пометив респондента ответившим |
| `GET` `POST` | `/api/surveys/{id}/experts` | Экспертные оценки |
| `POST` | `/api/surveys/{id}/import` | Загрузить CSV/XLSX |
| `GET` | `/api/surveys/{id}/export?format=csv\|xlsx` | Выгрузка |
| `GET` | `/api/surveys/{id}/template.csv` | Бланк под состав участников |

Пустые поля в ответах не выводятся (`non_null`), поэтому клиенту не нужно отличать
«нет значения» от нуля.

## Формат файлов импорта

Разделитель определяется автоматически: запятая, точка с запятой, таб или вертикальная черта,
что нашла в первой непустой строке. Первая строка — заголовок. Строки, начинающиеся с `#`,
пропускаются, кодировка UTF-8 с BOM читается.

**Длинный формат** — одна строка на один выбор:

```csv
From,To,Type,Rank
1,2,SYMPATHY,1
2,1,SYMPATHY,
3,,,
```

Колонки `From`, `To`, `Type`, `Rank` канонические; принимаются и прежние
`respondent`, `target`, `type`, `rank`, и русские названия.

* Строка с `From` и пустым `To` — «отвечал, но никого не выбрал». Без неё такой
  ответ неотличим от не ответившего, потому что строк выбора он не оставляет.
* Для антипатий ранг отрицательный: `-1` — «ненавижу больше всех», `-3` — последний.
* Шаблон (`/template.csv`) открывается пустым: строк-примеров в нём нет.

**Широкий формат** — строка на респондента, колонки помечены кодами участников;
значение — `1` (выбрал), `0` (не выбрал) или `-1` (антипатия):

```csv
code,1,2,3
1,0,1,1
2,1,0,0
```

Названия колонок «кто выбрал», «тип», «вид», «вес», «ранг» распознаются по-русски
и по-английски. Коды, которых нет среди участников, пропускаются с предупреждением.

## Как считаются показатели

**Ответили или нет** — отдельная отметка, а не вывод из числа выборов. Без неё
«отвечал, но никого не выбрал» и «не отвечал» неразличимы.

**Статусы** — по входящим выборам относительно среднего `μ` и разброса `σ`:
«предпочитаемый» = `floor(μ) + 1`, «звезда» = `max(ceil(μ + σ), предпочитаемый + 1)`,
«принятый» = `max(1, floor(μ − σ))`. Пороги можно задать вручную — тогда применяются
они. Если все получили одинаковое число выборов, разброса нет и правило не разделяет
группу: в ответе появляется флаг `degenerateThresholds`.

| Статус | Смысл |
| --- | --- |
| «Звезда» | выбирают чаще всех |
| «Предпочитаемый» | выше среднего |
| «Принятый» | на уровне среднего |
| «Низкопринятый» | набрал хоть немного, но ниже «принятого» |
| «Изолированный» | выбирал сам, но его не выбрал никто |
| «Отвергаемый» | набрал антипатий не меньше порога |
| «Аутсайдер» | отвечал, но никого не выбрал и его не выбрали |
| «Нет данных» | не отвечал; о нём ничего не известно |

«Нет данных» — это не изоляция: в списки изолированных и в числитель индексов
изоляции и отрицательного статуса такие участники не попадают.

**Индексы:**

- `gsc` — сплочённость группы: `2M / (n(n−1))`, где `M` — число взаимных пар.
  Формулу можно переключить на `mutualDoublePass` (свойство `sociometric.gsc-formula`),
  которая для ранжированного опросника с весами считает сумму произведений.
- `reciprocityIndex` — доля взаимных пар среди всех пар с хотя бы одним выбором.
- `density` — отношение числа связей к максимально возможному.
- `rejectedIndex` — доля участников, получивших хотя бы одну антипатию.
- `negativeStatusIndex` — доля участников с негативным статусом.
- `meanSelectionsPerPerson` — среднее число полученных выборов.

Подгруппы для сравнения выделяются по **ведущим цифрам кода**: «1А» и «1Б» попадают в
подгруппу «1», «2А» и «2Б» — в «2». Коды без цифр («1», «12») подгрупп не образуют.
Подгруппы меньше двух человек отбрасываются. Антипатии считаются внутри своей подгруппы,
поэтому подгруппа с отвержением не выглядит здоровой.

**Экспертные оценки.** Kendall W показывает согласованность экспертов (нужен минимум
двойной эксперт, иначе в UI пишется «нужно минимум два эксперта»). Kendall W требует
сбалансированной таблицы, поэтому оценённый не всеми участник выпадает целиком у всех
экспертов — подставлять средний ранг значит придумать оценку; в ответе видно, сколько
экспертов и сколько участников реально вошло в расчёт (`kendallExperts`,
`kendallParticipants`). Кого не оценил ни один эксперт, тот не получает «0»: ноль
означал бы оценку «самый непопулярный», поэтому средний балл не передаётся вовсе.
Пирсон и Спирмен сравнивают оценку эксперта с количеством полученных выборов, тоже
без вымышленных нулей. При недостатке данных все три поля возвращаются как `null`.

```
src/test/js/                 проверки фронтенда на node
```
